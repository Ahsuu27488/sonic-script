# Architecture (as built)

> The map of what actually exists. Update it whenever modules, data, interfaces, commands or flows change.
> Only real paths and names: every one here must exist in the code.

## Runtime

The Milestone 0 benchmark is a Python command-line tool run by hand on the owner's PC. It calls the Groq and
Gemini HTTP APIs directly with the user's keys; there is no SonicScript server. The M1 Windows app is being
built in Rust in `desktop/`: the platform-free core (`desktop/core`: text cleanup, voice gate, Opus encoding,
engine clients in a fallback chain, pipeline, key rules, resampler) and the app binary `sonicscript.exe` (`desktop/win`). Without
arguments it listens for the dictation key, records, prints the text and pastes it at the cursor (`inject`);
`--record`, `--file` and `--bench` run the same pipeline without the key.
The planned apps are described in `blueprint.md` §3 and §5.

```
record ──► spec/fixtures/audio/<id>.wav (16 kHz mono, trimmed)
bench  ──► encode (ffmpeg → Opus, cached) ──► engine (HTTP) ──► score ──► eval/results/<run>/results.jsonl
report ──► eval/results/<run>/report.html (self-contained, uses design/tokens.css)
```

## Data

- `spec/fixtures/audio/*.wav` and `free.json`: the owner's recordings and free-speech transcripts. Git-ignored
  (D-004). Written by `record`, read by `bench`, `probe`, `report`.
- `eval/results/<run>/results.jsonl`: one JSON line per request (engine, fmt, sentence, repeat, text, raw ASR,
  latency and stages, bytes, tokens, cost, error, score fields). Appended by `bench`; the latest line per key wins.
  Git-ignored. `eval/results/cache/<fmt>/` holds encoded audio.

## Interfaces

- Engine contract: `Engine.transcribe(EncodedAudio, sentence_id) -> EngineResult` (text, latency_ms, stages_ms,
  raw_asr, tokens, retries, error). Errors are returned, never raised.
- Gemini: `POST {base}/models/{model}:generateContent`, header `x-goog-api-key`, audio as `inline_data`; the
  speech-to-text model answers in `parts[].audioTranscription.text`, in the speaker's script.
- Groq and OpenAI: `POST {base}/audio/transcriptions` (multipart) and `POST {base}/chat/completions`,
  `Authorization: Bearer`.

## How a benchmark run flows

1. `__main__.main` (`bench`) → `build_engines` + `warm_up` (opens the TLS connections first).
2. `bench.run` encodes all clips, skips finished jobs, then runs one thread pool per provider (`concurrency`).
3. Per job: `audio.encode` → `Engine.transcribe` (`_send` rate-limits, times the successful attempt, retries
   429/5xx) → `scoring.score` → one JSON line.
4. `summarise` → `recommend` / `pick_format` → `report.build`.

## Configuration

- `GROQ_API_KEY`, `GEMINI_API_KEY`, `OPENAI_API_KEY` (paid, benchmark only): `eval/.env` first, then the process environment, then the Windows user
  environment (`HKCU\Environment`) (`config.load_env`).
- Model ids, prices, rpm budgets and per-provider `concurrency`: `spec/providers.json`. Presets: `bench.PRESETS`.

## Dictation pipeline (desktop/core)

```
key down ─► start chime (cue) ─► mic (cpal: the stream `Ready` set up beforehand, D-036) ─► mono ─► resample 16 kHz ─► encode::Stream (20 ms packets while recording)
key up / Enter ─► run_streamed:
samples (16 kHz mono) ─► vad::detect ─► no speech? → nothing sent
                      ─► packets for speech ± 500 ms ─► Ogg ─► Chain (D-029) ─► Normalizer::clean (per line)
text ─► console + inject::paste (dictation mode only; clipboard → Ctrl+V → clipboard restored)
     ─► history: whole recording (Ogg) + one line in history.jsonl (D-032; --no-history: nothing)
each engine in the Chain: speech call ─► format step (Groq, format-v1.md, D-030; only with --format since D-041, else the engine's
       own refine, if any)
Chain: Gemini Transcribe + Groq Roman cleanup ─(4 s or error)─► + Gemini Flash ─(3 s)─► + Gemini Flash-Lite
       (D-035: Gemini only; all fail → AllFailed, nothing typed, the console says why); an answer mostly in Urdu / Devanagari
       script that no refine or format step made Roman goes through the `romanize` step (D-039) or counts as failed;
       first good answer wins (the others run on and are ignored); a model out of free
       requests is skipped until Google's reset, also after a restart (resting.json); while the main model
       is out, the others are asked together (D-040)
```
