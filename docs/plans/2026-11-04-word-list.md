# My words: the personal word list (draft plan, not approved yet)

**Status:** draft for the owner, 2026-11-04. Built in steps: phase A with M1 step 6 (config file), phase B in M2
(settings page), phase C after that. Nothing here is decided until the owner says so (then a DECISIONS entry).

## The problem

The speech models already know almost every common word, name and brand. They fail on what is personal: the
user's own names, projects and products (Taskvane, SonicScript, Relay), friends' names, and words they spell their
own way. Live examples (dictation history, 2026-11-04): "Claude" → "McCloud" (Gemini Flash), "Taskvane" →
"Taskman". Nobody should have to type a dictionary: the list must fill itself as much as possible.

## What a word list is (one format everywhere)

A plain text list, one entry per line. The same format in the settings box, in a file, in what a chatbot writes,
and later on Android:

```
# My projects            (a line starting with # is a comment or a group name)
SonicScript
Taskvane = Taskman, Task vein          (after "=": how it gets misheard)
Claude = McCloud, Cloud
hun = hoon                             (a spelling I prefer: write "hun" where "hoon" comes out)
```

- Left of `=`: the word exactly as it should be written (casing kept).
- Right of `=` (optional): mishearings or other spellings, comma-separated; they are replaced by the left side.
- The paste box is forgiving: bullets, numbers, commas, "Word: note" or "Word — note" are cleaned up, duplicates
  merged, and the user sees "87 words found, 12 new" before saving.

## How words get in (the user picks any)

1. **Type or paste** them in the "My words" box (settings), or edit the file (`%APPDATA%\SonicScript\words.txt`,
   phase A: `sonicscript --words` opens it in Notepad).
2. **Import from your AI assistant** (the owner's idea). The box has a "Copy prompt" button; the user pastes the
   prompt into the chatbot they use every day (Claude, ChatGPT, Gemini, Claude Code, Codex, ...). From its memory
   and their past chats it writes the user's word list in the format above; the user copies the answer back into
   the box. Prompt below.
3. **Say them to your AI assistant** (the owner's second idea): the same prompt in "collect" mode: the user
   dictates words one by one into the chatbot ("add Taskvane, add Ahsan's friend Bilal ..."), says "done", and
   the chatbot prints the whole list in the format.
4. **Starter packs** (switches, off by default): "AI and tech" (Claude, ChatGPT, Gemini, GitHub, VS Code, ...),
   "Pakistan" (cities, common names), "Religious phrases" (InshaAllah, Alhamdulillah, MashaAllah in the user's
   preferred spelling), "Roman Urdu spelling style" (hai / hun / nahi vs hoon / nahin).
5. **Learning over time** (phase C), always as suggestions the user accepts with one click, never silent:
   - from the dictation history: names and English words that keep coming up and are not in the list;
   - from corrections: a word the user retypes right after a paste ("McCloud" changed to "Claude" within a few
     seconds, read back from the text field) becomes "Claude = McCloud";
   - use counts: words that are used often rank higher (see the limit below).
   Silent learning would also learn mistakes; one click keeps the user in charge.

## How big can the list be? (the owner asked Claude to decide)

**No limit on the list itself.** What matters is what goes into each request, and that is kept small by the app:

- **Gemini audio prompt** (Flash, Flash-Lite): the list is a hint of words that may come up ("these names may be
  spoken: ..."). Gemini's limits are large, so up to about 300 entries go in, ranked by use; more than that adds
  cost and slowness for little gain. Transcribe takes no prompt (audio only), so for it only the next two apply.
- **Format step** (Groq `gpt-oss-120b`, `{word_list}` in `format-v1.md`): only the entries that sound close to a
  word in this transcript (the local sound-skeleton match from D-019), usually 0-10. This matters: Groq's free
  tier allows 8K tokens a minute and a format call is already ~1,300 tokens, so the whole list there would halve
  the dictations per minute.
- **Local cleanup** (`normalize.rs`, D-019, already built): exact and sound-alike matches after any engine, free
  and instant; the "=" mishearings become exact replacements.
- Never in the Whisper prompt (D-014: it makes Whisper translate).

## More context, fewer words needed

- **The app in front** (already in the history): "the user is typing into Claude / WhatsApp / VS Code" in the
  audio prompt. It costs a few tokens and fixes many names without any list ("McCloud" in the Claude app).
- **The window title** (opt-in: it is sent to the engine): VS Code's title holds the project and file name, a chat
  app's title the contact's name.
- Both go into the Gemini audio prompt (Flash, Flash-Lite) and the format step; Transcribe gets them through the
  format step.

## The prompt for the user's AI assistant (draft)

```
I am setting up SonicScript, a dictation app that types what I say (Urdu, Hindi and English, written in Roman
Urdu / Hinglish). It needs my personal word list: words a speech recognizer cannot guess. Using what you know
about me (your memory and our past chats), list:
- names of people I mention (family, friends, colleagues, clients)
- my projects, products, companies, channels, apps I build
- tools, apps, brands and technical terms I use that are not everyday words
- places that matter to me
- words I spell in my own way (my Roman Urdu spellings)
Leave out ordinary words any recognizer knows. Do not invent anything: only what you actually know about me.

Write only the list, in this exact format, nothing before or after it:
# Group name
Word
Word = how it might be misheard, another spelling

If you know little about me, say so in one "# " line and list what you do know.
Collect mode: if I say "collect", ask me for words one at a time (I may dictate them); when I say "done",
print the whole list in the format above.
```
